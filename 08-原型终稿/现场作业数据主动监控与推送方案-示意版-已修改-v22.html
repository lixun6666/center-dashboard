GOFO现场作业数据主动监控与推送方案
业务价值 接收对象 触发机制 推送示例 异常闭环 效果衡量
方案目标

从“人找数据”到“数据找人”

不是增加一种消息渠道，而是让问题更早被发现、更快被处理，并持续跟踪到关闭。

当前方式
人发现问题→查系统 / 盯大屏→判断→处理
→
目标方式
业务数据→系统识别→推送责任人→处置闭环
核心判断：只有看到数据后，业务能够直接判断或采取动作的数据，才值得主动推送。
01 / WHY & WHAT

3类主动推送，操作日小结统一承载作业与质量结果

按使用时点收敛消息；BI负责质量指标口径和结果计算，小结在班次结束后发送并展示BI最新可用结果。

◉

分拣小时播报

一条消息并列展示时分拣、已分拣、已签出、应分拣、待分拣、待签出、货量预测（不在本期）和预计到车。

时分拣已分拣已签出应分拣待分拣待签出货量预测（不在本期）预计到车
!

作业关注提醒

集中展示即将到达关键节点或已经异常的卸车、发车、离场和签出任务，并定位到具体车辆、任务或目的组织。

已到未卸即将发车未离场截单后待签出
⌁

操作日作业小结

合并中心作业、异常区作业和BI质量监控结果，统一汇总作业完成、期末待办和质量表现；下一操作日预测作为后续能力示意。

中心作业异常区作业质量监控操作日交接下一操作日预测（不在本期）
收敛结果：每小时只保留1条分拣播报；临期或异常按条件提醒；班次结束后形成1条操作日作业小结。
02 / WHO

谁能处理，就推给谁

接收对象不是订阅名单，而是责任链路。消息需要与业务动作对应。

分拣组 / 调度组 小时作业

接收：分拣小时播报

动作：调人、调设备、消化待办、保障后续发运

卸车组 / 装车组 / 分拣组 / 调度组 作业关注

接收：作业关注提醒；按卸车、发车、离场和签出责任定向触达

动作：上传BOL、完成卸车、提前准备发车、推动车辆离场并处理截单后待签出货量

仓长 / 组长 / 异常组 操作日管理

接收：操作日作业小结，统一查看中心、异常区和HUB质量监控结果

动作：安排期末待办、处理时效风险、跟进不达标指标并完成下一操作日交接

03 / WHEN

不同数据，采用不同触发机制

统一“每小时推一次”会让正常信息和异常信息混在一起，最终造成消息疲劳。

定时播报

分拣小时播报

合并时分拣、已分拣、已签出、应分拣、待分拣、待签出、货量预测（不在本期）和预计到车。

每小时一次
上一完整小时 + 操作日累计 + 当前状态
节点 + 条件

作业关注提醒

每类提醒都同时定义首次触发、重复提醒和停止发送规则，明确系统何时开始推、多久继续推，以及最晚推到什么时候。

达到首次触发条件 → 定向推送 → 未处理按固定间隔重复 → 状态完成 / 取消立即停止；达到最晚发送时间也停止
班次结束

操作日作业小结

班次结束后汇总中心和异常区作业，同时带入BI最新可用的质量监控结果；质量数据单独标明日期，不阻塞小结发送。

班次结束 → 汇总中心与异常区作业 → 带入BI最新可用质量数据 → 发送
触发原则：小时播报掌握实时作业，作业关注提醒覆盖临期准备和异常处置，班次结束后通过操作日小结完成作业交接并同步质量结果。

05 / CLOSED LOOP

消息发送不是结束，风险或待办关闭才是结束

条件提醒由风险状态驱动；操作日作业小结中的遗留事项必须进入下一操作日交接。

风险产生业务状态变化
系统识别命中阈值与规则
首次提醒结论、责任人、要求
责任人确认已知晓 / 处理中
持续监控判断是否改善
再次提醒未处理且仍在发送时限内
状态恢复达到恢复规则
关闭与留痕记录时长与结果
重复提醒：只在未确认、风险恶化、超过处理时限或状态恢复时再次发送。
06 / RESULT

最终衡量“是否更早发现、更快处理”

不能用“每天发了多少条消息”衡量价值，消息数量甚至应该随着运营改善而下降。

风险发现效率车辆滞留、待签出超时和产能风险从发生到首次识别的平均时长。
风险处理效率首次提醒到责任人确认、状态恢复和风险关闭的平均时长。
现场运营改善已到未卸等待时长、关键发车节点准备情况、待驶出围栏时长、截单后待签出、异常区超时待办及人工查系统次数是否改善。
1风险阈值多久、多少或多严重需要提醒
2重复提醒持续多久再次触达
3停止时限超过多久后不再继续推送
4恢复规则什么状态代表问题关闭
5数据口径班次、预测、围栏、节假日及分拣总量
